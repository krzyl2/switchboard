# Decisions

Small choices the documentation left open, one line each. Larger ones that need the maintainer are listed in the stage report, not here.

## Stage 0

- 2026-10-23 — HA WebSocket client is in-house (`System.Net.WebSockets`), not NetDaemon: protocol is small, removes version coupling, and Stage 1 needs `subscribe_entities` with `last_reported`.
- 2026-10-23 — Outbound HA commands go through an explicit allow-list; Stage 0 allows only `ping` (besides `auth`). There is no raw send path; `call_service` is structurally impossible.
- 2026-10-23 — MQTT publishes go through a topic guard: only `switchboard/…` and `homeassistant/<component>/switchboard/<object_id>/config`. Topics such as `zigbee2mqtt/<x>/set` command real devices.
- 2026-10-23 — Projects: `Switchboard.Application`, `Switchboard.Infrastructure`, `Switchboard.Host` (Web merged into Host until Stage 4). `Switchboard.Domain` is created with its first type in Stage 1 rather than empty now.
- 2026-10-23 — Single test project `tests/Switchboard.Tests`; xunit.v3 in VSTest mode so plain `dotnet test` works.
- 2026-10-23 — Clock is `System.TimeProvider`; tests use `FakeTimeProvider`. `Microsoft.CodeAnalysis.BannedApiAnalyzers` fails the build on `DateTime.Now`, `Thread.Sleep`, `Task.Delay`/`PeriodicTimer`/`WaitAsync`/`CancellationTokenSource` overloads without a `TimeProvider` (tests included).
- 2026-10-23 — Operational parameters live in `src/Switchboard.Host/appsettings.json` under `Switchboard`, bound to options with required properties, `ValidateOnStart` and `ErrorOnUnknownConfiguration` (a misspelt key fails startup).
- 2026-10-23 — Mode resolution is fail-safe: only the exact string `active` yields active; anything else, including a missing or broken `options.json`, is shadow. Stage 0 has no command path, so `active` only logs a warning.
- 2026-10-23 — Standalone path (no `SUPERVISOR_TOKEN`) reads `SWITCHBOARD_HA_URL`, `SWITCHBOARD_HA_TOKEN`, `SWITCHBOARD_MQTT_HOST/PORT/USERNAME/PASSWORD`, `SWITCHBOARD_MODE`, `SWITCHBOARD_LOG_LEVEL`; `SWITCHBOARD_MQTT_PORT` defaults to 1883. Standalone MQTT has no TLS.
- 2026-10-23 — Add-on mode takes MQTT credentials only from the Supervisor (no env fallback), refetched on every connect; Supervisor `ssl: true` is honoured.
- 2026-10-23 — HA connect and handshake receives are bounded by `HomeAssistant:PongTimeout`, so a peer that never sends `auth_required` cannot hold the link in "connecting".
- 2026-10-23 — After `auth_invalid` the client waits `ReconnectMaxDelay` before retrying; the token is never logged.
- 2026-10-23 — Bearer header is also set on the WebSocket upgrade (the Supervisor proxy needs it, per Argus).
- 2026-10-23 — Health = HA WebSocket authenticated with keepalive answered AND MQTT connected. Published at start and every `Heartbeat:Interval`; MQTT reports connected only after availability and discovery are out, so HA never sees state before its config.
- 2026-10-23 — All MQTT publishes and the last will are QoS 1; availability and discovery retained, state not retained.
- 2026-10-23 — `binary_sensor.switchboard_healthy` carries no `device_class`, `entity_category` or `origin`; suggested entity id via `default_entity_id` (accepted by HA 2026.10.0 without warnings, verified in e2e).
- 2026-10-23 — Ingress guard runs first; requests without a remote IP are refused; `X-Ingress-Path` becomes `PathBase` only when it is a single well-formed path. Unknown `/api/*` routes return 404, not the SPA shell.
- 2026-10-23 — Host: `InvariantGlobalization=true`, `UseAppHost=false` (identical publish output for every arch), `IncludeSourceRevisionInInformationalVersion=false`.
- 2026-10-23 — Logging: Microsoft.Extensions.Logging SimpleConsole, single line, timestamped; level from `log_level`. Secret-holding types redact `ToString`.
- 2026-10-23 — Runtime base `ghcr.io/home-assistant/base-debian:trixie-2026.10.0` (Debian 13), not Argus's bookworm: the current HA base line.
- 2026-10-23 — ASP.NET Core runtime 10.0.13 installed with `dotnet-install.sh` (pinned version, unpinned script — it has no versioned URL). It is 10 days old, under the two-week rule, but it is the runtime that ships with SDK 10.0.402 and a security release.
- 2026-10-23 — s6: `S6_CMD_WAIT_FOR_SERVICES=0` (a crash at start otherwise deadlocks the halt), `S6_SERVICES_GRACETIME=8000`, `S6_KILL_GRACETIME=1000` (fits the Supervisor's 10 s stop). `finish` records the exit code, stops respawn and halts the container.
- 2026-10-23 — Image label `io.hass.type="app"` (current Supervisor naming); `io.hass.arch` uses HA arch names (`amd64`, `aarch64`). No `EXPOSE`.
- 2026-10-23 — `switchboard/Dockerfile.dockerignore` is an allow-list so `deploy/dev-data` and tokens never enter the build context.
- 2026-10-23 — GitHub owner `krzyl2` and maintainer line copied from Argus (provisional until the repository exists).
- 2026-10-23 — Store description keeps the docs/06 sentence and appends "Best-effort; not a protective device." — the CLAUDE.md hard rule outranks the verbatim manifest text.
- 2026-10-23 — SPA: Preact 10.x (not 11, its test library lagged the cutoff), Vite 8, TypeScript 7, Vitest 5; lockfile resolved with `npm install --before=2026-10-09` so transitive deps respect the two-week rule too.
- 2026-10-23 — SPA hides last known values on any fetch failure and shows "status unavailable" with the last successful update time; status payload parsed strictly. System fonts only (no web fonts).
- 2026-10-23 — Polish vocabulary follows the mockups: shadow = „Obserwacja", active = „Sterowanie aktywne", health = „Kondycja".
- 2026-10-23 — No light/dark toggle in Stage 0; `prefers-color-scheme` only. The toggle arrives with the runtime UI (Stage 4).
- 2026-10-23 — Placeholder `icon.png`/`logo.png` generated by `deploy/generate-placeholder-art.py` (stdlib only).
- 2026-10-23 — Dev stack: HA 2026.10.0, mosquitto 2.0.22, ports bound to 127.0.0.1 only; e2e passes the HA token through the process environment and never writes `deploy/.env`. The dev HA owner gets a random, unprinted password per run.
- 2026-10-23 — Dedicated buildx builder `switchboard-builder` for multi-arch builds; other builders untouched.
- 2026-10-23 — MQTT keep-alive is explicit: `Switchboard:Mqtt:KeepAlivePeriod` = 15 s (the MQTTnet default the e2e observed), validated `< Heartbeat:ExpireAfter`. It decides how fast a hung process turns the health entity unavailable, so it is not left implicit.
- 2026-10-23 — `Switchboard:Mqtt:ShutdownTimeout` = 4 s bounds the OFF → offline → disconnect sequence; a packaging test keeps `2 × ShutdownTimeout ≤ S6_SERVICES_GRACETIME`. `HostOptions.ShutdownTimeout` stays default (lowering it alone made the process die by SIGABRT).
- 2026-10-23 — MQTT reconnect backoff resets only after availability, discovery, state and subscribe succeed, not on CONNACK. A session that fails while still connected is left with a best-effort retained `offline` and a clean disconnect before retrying.
- 2026-10-23 — `finish` logs SIGTERM at info and any other signal or non-zero exit as fatal before halting.
- 2026-10-24 — MQTT identity scheme approved by the maintainer and frozen as an API: unique_id `switchboard_<object_id>`, discovery `homeassistant/<component>/switchboard/<object_id>/config`, state `switchboard/<object_id>/state`, availability `switchboard/availability`, device `["switchboard"]` (`MqttIdentity`).
- 2026-10-24 — Build-only npm dependencies under MPL-2.0 / CC-BY-4.0 / BlueOak / CC0 (Vite 8 toolchain) accepted by the maintainer; nothing outside MIT/BSD/Apache ships in the image.
- 2026-10-24 — Liveness is a Docker `HEALTHCHECK` (`curl` to `http://127.0.0.1:8099/api/status`, 30 s / 5 s / 3 retries, 30 s start period) instead of `watchdog: tcp://…` (connects even to a frozen process). `startup`, `boot`, `ingress_port` dropped from config.yaml as Supervisor defaults; the add-on linter now passes clean.
- 2026-10-23 — DOCS.md shed-loads example uses a template binary_sensor helper with `delay_on: 60 s` plus a `time_pattern` backstop; a plain state trigger with `for:` restarts its timer on every off ↔ unavailable flap (and the previous example did not load in HA 2026.10).

## Stages 1–5 (orchestration, decided up front so every stage builds on the same ground)

- 2026-10-24 — Configuration document: `switchboard.yaml`, YAML, snake_case keys exactly as in `03-ARCHITECTURE.md` (`signals:`, `devices:`, `circuit_groups:`), plus `schema_version: 1`, `connection:` (topology, breaker rating, characteristic, voltage, reserve per phase) and `control:` overrides. Read as untrusted (schema-validated); an invalid document keeps the system in safe state and the UI says what is wrong.
- 2026-10-24 — The configuration document lives in the add-on config folder (`map: addon_config`, `/config/switchboard.yaml` in the container, `/addon_configs/<slug>/switchboard.yaml` on the host) so it can be edited by hand (Studio Code Server, Samba) before the wizard exists and is included in backups. Runtime state and the decision log stay in `/data`. Supersedes "`/data` holds the configuration document" in 06-DEPLOYMENT.md.
- 2026-10-24 — Control-parameter defaults (04 §7 table, tier table, budget thresholds) ship as an embedded YAML defaults file, never as C# literals; `control:` in the user document overrides them key by key.
- 2026-10-24 — Runtime state `/data/state.json` (schema-versioned): applied device states, overload budgets, UI mode choice. Lockout timers are never persisted as expiries; every lockout restarts from the restart instant (SAFE-07).
- 2026-10-24 — Decision log: `/data/decisions/YYYY-MM-DD.jsonl` (UTC day), one decision per line with reason code and inputs; retention in days from configuration. Only state changes and refusals are logged, not every unchanged cycle.
- 2026-10-24 — Mode: the add-on option (or `SWITCHBOARD_MODE`) is a hard ceiling. Option `shadow` forces shadow regardless of anything else. Option `active` lets the UI switch between shadow and active at runtime (MODE-02), persisted in `state.json`. Going active therefore needs two deliberate acts.
- 2026-10-24 — Reason-code list version 2: `headroom_available` and `kill_switch` added (04 §6).
- 2026-10-24 — Phase self-test (CONN-05) is a user-initiated command on a declared device, logged with `manual_override`, still subject to protection; it is the only command possible in shadow mode. SUPERSEDED 2026-10-25: the self-test is passive (Stage 5).
- 2026-10-24 — Commands (Stage 3+) reach HA only as `call_service` built by the EffectorGate for a declared actuator, a service allowed for that device type, in active mode (the self-test no longer commands anything: SUPERSEDED 2026-10-25, Stage 5). The WebSocket allow-list gains `subscribe_entities` (Stage 1), registry/state reads for discovery (Stage 5), and `call_service` only through that typed path.
- 2026-10-24 — No new Home Assistant instance is started for verification (maintainer's instruction). Verification: virtual-clock tests, a replay harness over 72 h of recorded history from the maintainer's installation (`tests/fixtures/replay/`, read through the HA history API), a dev replay mode (`SWITCHBOARD_DEV_REPLAY`, standalone only, effector replaced by a recorder) for UI checks, and shadow-mode runs on the live installation. The "fake meter driven by input_numbers" dev harness from 09-ROADMAP is replaced by in-process scenario harnesses.
- 2026-10-24 — Recorded history (`tests/fixtures/replay/live-*.csv.gz`) is the maintainer's real household consumption and the repository is public, so it is gitignored until the maintainer approves publishing it. Replay tests over it run in category `LiveReplay` and fail loudly if the file is absent; a committed synthetic fixture with the same shape covers the same rules everywhere.

## Stage 1 (Signals)

- 2026-10-24 — `Switchboard.Domain` created: BCL only (module-boundary test), unit types `Amperes`/`Watts`/`Volts`/`KilowattHours`/`Percent` with same-unit arithmetic only and no cross-unit conversion.
- 2026-10-24 — SIG-04 by type: Guard reads `ProtectionInputs` (amperes only), Dispatch reads `DispatchInputs` (watts and volts only); the full snapshot reaches `/api/signals` only. Architecture tests enforce all three.
- 2026-10-24 — Entity IDs exist only in the signal and configuration layer (`EntityId`, validated with Home Assistant's own `VALID_ENTITY_ID` rule); a source scan refuses entity-ID literals in `src/`.
- 2026-10-24 — Configuration v1: `schema_version`, `connection` (topology, `breaker_rating_a`, `characteristic`, `voltage_v`, `reserve_w` per phase, default from `control.connection.default_reserve_w`), `signals.<name>` (entity, kind, unit, sign, direction_from, max_age, sigma, role, phase, unavailable_as_zero), `control`. `devices`/`circuit_groups` reserved (warning `reserved_key_ignored`). Closed list of issue codes, each with path, line and column.
- 2026-10-24 — Signal kind `voltage` added to the kinds in 03; `direction_from` names a logical signal, not an entity, because resolving direction needs that signal's sign convention.
- 2026-10-24 — Sign is read at the house busbar: `positive_import` = a positive raw value flows into the busbar (grid import, inverter production). Internally import is positive.
- 2026-10-24 — Roles are a closed list: `phase_current`, `phase_power`, `phase_voltage`, `inverter_power`, `inverter_phase_current`, `total_current`, `total_power`. Signals without a role are display-only.
- 2026-10-24 — An invalid or missing document clears the store: no signal is valid, L1–L3 report `configuration_invalid`. No fallback to an earlier document. A reload that changes kind, unit or sign re-reads the last raw state under the new definition.
- 2026-10-24 — Reload: content-hash poll on the `TimeProvider` (5 s) is the source of truth, `FileSystemWatcher` only brings it forward, 500 ms debounce. YAML anchors, tags, duplicate keys, multiple documents, depth > 32 and files > 256 KiB are refused.
- 2026-10-24 — Control defaults: embedded `src/Switchboard.Infrastructure/Configuration/control-defaults.yaml` is the complete parameter list (04 §1, §7, signal and reserve parameters). `control:` merges key by key, lists replace whole, unknown keys and out-of-range values are errors.
- 2026-10-24 — Tier bands: `up_to` inclusive (I/In ≤ up_to). Characteristic C ships identical to B (IEC 60898 gives B and C the same thermal points 1.13/1.45 × In; only the magnetic trip differs) — conservative reading of 04 §1 "C shifts the table up", pending the maintainer. `unknown` caps the continuous multiple at 1.00.
- 2026-10-24 — Freshness: report time = `lr`, else the newer of `lu`/`lc`, clamped to arrival; stale when age ≥ `max_age` (deadline timer). `max_age` required per signal, at most `signals.max_age_limit` (24 h default). A repeat confirms freshness only when HA's own unclamped `last_reported` moved forward. A backward clock step forgets every sample (fail safe) and probes every signal once.
- 2026-10-24 — Freshness probe (provisional, pending the maintainer — it deviates from 03 "never poll"): `subscribe_entities` never delivers `last_reported` for a repeated value, so after `0.5 × max_age` of silence the store reads that one entity with REST `GET /api/states/<entity>` (Supervisor proxy). Read-only, structurally limited to a validated entity ID. Without it an idle phase reporting a constant 0.00 A would go stale and force a false safe state.
- 2026-10-24 — HA allow-list is exactly `ping`, `subscribe_entities`; every outgoing message is shape-checked. Reconnect backoff resets only after a session delivered the subscription's initial state.
- 2026-10-24 — Refresh detection: 0.25 quantile of the last 64 pushed-report intervals, at least 8 (a repeated value sends nothing and doubles the interval, so the median overstates). Initial states and probe answers excluded.
- 2026-10-24 — Minimum safe reserve: `R_min = max(floor, step − (m* − 1)·In·V + k·σ·V)`, `m*` = top of the highest non-shedding band that tolerates refresh + shed latency (+ one dispatch cycle for reduce bands). Flagged when the configured reserve is lower, never enforced. 631.5 W for the reference installation.
- 2026-10-24 — Direction (SIG-03): an unsigned current takes its sign from the `direction_from` power of the same poll (power may be newer than the current, or at most `max_skew` older; on expiry the power is probed once). Unknown, stale or misaligned direction = cautious mode: counted as import, protection data stays valid.
- 2026-10-24 — Balance check (SIG-09): per phase, one-sided (rejects only an impossible negative residual), inputs compared only within `max_skew`. A refused sample leaves the held value in use until its own `max_age`; phase current is never an input. Skipped when generation is not measured (no inverter, or `unavailable_as_zero`). Device terms stay empty until Stage 3.
- 2026-10-24 — Per-phase generation is split by inverter phase currents, else equally; an inverter mapped but not fresh makes house load unknown, not equal to import. `unavailable_as_zero` counts only `unavailable` (the inverter asleep), never `unknown`.
- 2026-10-24 — Dev replay: `SWITCHBOARD_DEV_REPLAY` scales the application clock to data time, standalone only (refuses add-on mode), never connects to HA.
- 2026-10-24 — `GET /api/signals`: camelCase, snake_case enum values, ages computed at request time, phase `residualAt`. SPA hash routes `#/` and `#/signals`. `index.html` `no-cache`, `/assets/*` immutable.
- 2026-10-24 — Stage 1 publishes no new MQTT entity, persists nothing in `/data` and makes no decisions (no reason codes).
- 2026-10-24 — `Directory.Build.props` `<Version>` follows `config.yaml` (packaging test). `System.Net.Http.HttpClient` logs at Warning so Supervisor and probe requests do not flood the add-on log.
- 2026-10-24 — For Stage 2 (orchestrator): the tier table gets a safety envelope that `control:` cannot override, built from the IEC 60898 thermal points in the defaults file (open band sheds everything at 0 s; no `may_add`/`hold` above the continuous multiple; `may_add` only up to 1.00 × In; continuous multiple ≤ 1.13). The hard rule "no configuration may raise a load above a phase limit" settles it; the C table is the maintainer's to widen.
- 2026-10-24 — For Stage 2 (orchestrator): the M1 current lags its own power by one poll in ~0.4 % of polls (72 h recording, up to ~12 A), so the reserve derivation counts one extra refresh of blind time (`signals.current_lag_polls`, default 1). Protection still reads current only.
- 2026-10-24 — Live check of 0.2.0 (shadow): configuration hot-loaded without restart, 13 signals fresh and equal to HA states, M1 current direction follows the signed M1 power, refresh 10 s detected, min. reserve 632 W; max_age 5 s on grid_current_l1 turned it stale at age ≥ 5 s with L1 protection data invalid, reverted. SIG-05/07/09 stay open (dependent devices, onboarding display, device terms).

## Stage 2 (Guard)

- 2026-10-24 — Device schema: `devices:` is a list in the 03-ARCHITECTURE shape, keyed by `id` (DeviceName `^[a-z][a-z0-9_]{0,39}$`, never contains '.'). Types are onoff | stepped | modulating with `reaction_time` (the DISP-01 / 03 vocabulary, replacing the brief's relay | relay_stages | modulating_current and shed_speed). Display names arrive later as an added key; schema_version stays 1.
- 2026-10-24 — Device applied state is read through State-kind signals the parser creates per stage (`device_<id>` or `device_<id>_stage<n>`, role device_state, entity = state_entity or the actuator, max_age = state_max_age, default `devices.state_max_age: 10m`). User signal names starting with `device_` are reserved.
- 2026-10-24 — ProtectionInputs carries ProtectionSetup (breaker profile, reserve in A, budget, timing, device specs with no entity IDs and no watts) and per-stage device-state samples, so the Guard reads configuration and device state from the same atomic snapshot. The reserve is converted from W to A only in the signal layer (`SignalUnits.CurrentAt`).
- 2026-10-24 — `SignalArchitectureTests.Consumer_views_carry_no_entity_ids` treats DeviceName as a leaf type. Its pattern excludes '.', so a string reached through it can never be an entity ID; a new test asserts that.
- 2026-10-24 — Safety envelope: a non-overridable `limits:` section in control-defaults.yaml. It enforces continuous multiple ≤ 1.13, unknown ≤ 1.00, may_add only up to 1.00 × In, the open band shed_all at 0 s, and above the continuous multiple a finite allowed duration and no may_add/hold reaction. `control.limits` is key_not_allowed; a violation is tier_envelope_violated with path and line.
- 2026-10-24 — Reserve derivation uses `signals.current_lag_polls: 1` and T_blind = (1 + lag)·T_refresh + shed_latency. The reference installation with a detected 30 s or 10 s refresh stays at 631.5 W, because a T_blind of 75 s still fits the 3 min band. With refresh undetected and max_age 90 s the minimum rises from 631.5 W to 1321.5 W. The 1.25× band is now lost above a 67.5 s refresh (it was 135 s).
- 2026-10-24 — The breaker model compares I/In with up_to (inclusive), never I with up_to×In, so band boundaries are exact in floating point. Protection uses the current magnitude, because the breaker heats on export too.
- 2026-10-24 — 04 §2 'stop at the first match' is implemented as 'the most severe reaction wins' across tier band, band timer and budget. The result is identical when the sources agree and strictly safer when an exhausted budget meets a mild band.
- 2026-10-24 — Band allowed durations are enforced by a per-band timer on the measured current: at expiry one step is shed at that instant, then one per new sample. This is in addition to budget consumption, because with c = 1.13 the 1.00–1.13 band never consumes budget.
- 2026-10-24 — Reaction timing adds no new parameters. reduce_ordinary_cycle acts after dispatch.persistence_down_cycles boundaries; reduce_next_cycle acts at each boundary; shed_one acts per new phase sample; shed_all acts at once. Boundaries are multiples of dispatch.cycle since the Unix epoch. Limits are released after dispatch.persistence_up_cycles boundaries at or below the reserve threshold with budget ≥ stop_increases_below.
- 2026-10-24 — Pending relief: the rated ΔI of guard-limited steps whose applied state still shows on is subtracted from the measured current for further shed decisions. This is the shadow 'as if applied' model and a minimal in-flight estimate. Budget, tier display and violation checks always use the measured current.
- 2026-10-24 — The budget is committed per phase sample on the meter's timeline, using the larger of the previous and new multiple, because the rise may have happened right after the previous report. Between samples it is projected with the last multiple. It holds while data is invalid or time steps back.
- 2026-10-24 — Modulating devices are only reduced to min_a in Stage 2: they have one actuator and no stop path. Their min_a draw stays as unsheddable load.
- 2026-10-24 — Lockouts never outrank protection. Every Guard intent is Protective: it ignores min_on (recording overridden lockout_min_on) and the step limit. The gate's min_on refusal and one-stage-per-cycle limit apply to Ordinary intents (Stage 3 Dispatch); excess changes are dropped for that cycle without a record.
- 2026-10-24 — Safe-state reasons: a phase current that is stale, rejected, unavailable or missing gives guard_stale_signal. Awaiting first sample, HA disconnected, invalid or missing configuration, no snapshot yet and shutdown give safe_state. An invalid configuration targets the last valid device set of this process.
- 2026-10-24 — A stale or unknown device-state signal makes that device unsafe, counts it as on at full rating, and records a would-switch-off for it (guard_stale_signal).
- 2026-10-24 — An over-limit current on a phase that is exporting is recorded (action cannot_reduce_exporting, reason guard_tier_exceeded) and never shed, because shedding would raise the current.
- 2026-10-24 — A guard limit release is logged per device with headroom_available. Leaving safe state or the kill switch is a single phase or system record, with no per-device lines.
- 2026-10-24 — Decisions carry the cause as reason, plus mode, commanded=false and refused_by=mode_shadow in Stage 2. A ModeResolved decision is logged at every start. With the add-on option set to active the note is active_unavailable_before_stage_3 and the effective mode stays shadow. /api/status.mode reports the effective mode.
- 2026-10-24 — Decision log: one file per UTC day; id = unix ms + a per-process counter. A partial last line is isolated by appending a newline at start. An unwritable log never stops the Guard. Retention deletes a file only if it is older than retention_days and not among the newest retention_days files, so a forward clock jump cannot wipe history.
- 2026-10-24 — state.json is validated strictly. A corrupt file is renamed `state.json.corrupt` and the add-on starts from fresh defaults. Budgets are saved immediately on threshold crossings and on decreases ≥ 0.05 (bounding how optimistic a crash can make them), otherwise at most every minute. Persistence timing lives in appsettings `Switchboard:Persistence`.
- 2026-10-24 — The data directory comes from the new environment variable `SWITCHBOARD_DATA_PATH` (default /data); the test host and dev replay point it at a temp directory.
- 2026-10-24 — MQTT object_ids are frozen now: `l<n>_headroom`, `l<n>_headroom_power`, `l<n>_breaker_headroom`, `l<n>_overload_budget`, `l<n>_recovery_remaining`, `l<n>_guard_state`, `mode`, `last_decision`, `kill_switch` (switch) and `device_<id>_guard_state`. Unknown values are published as `None`. The retraction ledger is kept in state.json.
- 2026-10-24 — Kill switch inbound: the subscription guard allows exactly `<prefix>/status` and `<base>/kill_switch/set`. The payload must be exactly ON or OFF, and retained command messages are ignored so a stale retained OFF cannot lift the kill switch on reconnect.
- 2026-10-24 — POST /api/guard/kill-switch requires Content-Type application/json, which forces a CORS preflight from foreign origins.
- 2026-10-24 — The HA allow-list gains unsubscribe_events with exact shape {id,type,subscription}. subscription is restricted to the client's own non-active subscription ids.
- 2026-10-24 — The SPA Guard view is labelled 'Limits'/'Limity' (mockup vocabulary, and it avoids protection wording). The kill switch in Polish is „Wyłącznik awaryjny sterowania”.
- 2026-10-24 — Maintainer example values: heaters 0.35 per kWh and the charger 2.03 per kWh (mockup values; the house prefers charging the car). Heaters are rated 6.6 A (1500 W / 230 V, rounded up).
- 2026-10-24 — Summed topology (degraded mode per D2): a phase without its own current uses the total magnitude as worst case.
- 2026-10-24 — Pins: none. Stage 2 adds no dependency to the .NET solution or the SPA.
- 2026-10-24 — Effective current subtracts relief only for held stages whose fresh state shows load (relay on, a fresh setpoint). An unknown or stale stage relieves nothing but still counts as on when choosing what to shed. A modulating device that cannot switch off relieves at most setpoint − min.
- 2026-10-24 — Release persistence (persistence_up_cycles good boundaries) restarts at every hold cause at evaluation time: an invalid phase, a system safe state, the kill switch, or a new hold. It is applied after the boundary records, so the boundary of a new hold never counts as good.
- 2026-10-24 — System-wide safe-state records carry a cause (shutdown, starting, configuration_invalid, configuration_missing, source_disconnected, meter_invalid), and a new cause is a new safe_state_entered record. ProtectionInputs carries SetupAbsence (not_read, invalid, missing). JSONL key safe_state_cause (written only when present); API inputs.safeStateCause (always present, nullable).
- 2026-10-24 — At shutdown the phases keep their real validity, so shutdown records carry the last phase picture. Tier reactions and boundary records do not run while a system safe state is active.
- 2026-10-24 — Decisions that end a condition (kill_switch_disengaged, safe_state_exited) keep the reason code of the condition that ended, but the UI words them by action ('The kill switch was released.', 'Valid data again; the safe state ended.').
- 2026-10-24 — total_current marks devices as dependents (SIG-05) only in three_phase_summed; elsewhere it is display only.
- 2026-10-24 — The safety envelope gains limits.budget_recovery_time_min: 600s (the shipped value). A shorter control.budget.recovery_time is tier_envelope_violated at control.budget.recovery_time (existing issue code reused).

- 2026-10-24 — Guard tier steps, reserve request, IncreasesAllowed and the envelope use I_est = measured + Σ in-flight deltas (shadow would-starts included). The open band, budget, tier display and violation analysis stay on measured.
- 2026-10-24 — The dispatch envelope is in amperes, from the guard: min(In − reserve, may_add_top × In) − I_est, per phase and per group phase. - 2026-10-24 — Lockouts have two timelines. Physical (Stage 2, used by the guard) is unchanged. - 2026-10-24 — Logging policy: target changes, lockout deferrals (once), override changes, unresponsive transitions, settling timeouts and foreign-load events are logged. Headroom refusals, confirmation waits, window waits and step-limit drops appear in GET /api/dispatch only.

- 2026-10-24 — Unresponsive: settling.mismatch_limit consecutive mismatches mark the device device_unresponsive. The power factor kept the right sign in 431 of 433 wrapped and 377 of 379 zeroed samples. Rules: within ±`power_factor_deadband_pct` (20) counts as import; a negative factor counts as export only after it has stayed negative for `export_hold` (30 s), so a one-poll glitch never blocks shedding; every other case is import. The phase power stays the dispatch input, unchanged (its wrap and zeroing are a separate fix). Opt-in by hand-editing `switchboard.yaml` only: the setup wizard still writes `direction_from` as the phase power and would undo it on save (known gap, not yet handled).

- 2026-10-28 — Settling (0.11.3, supersedes the "fresh at open" rule above): the closing set is the meter inputs only (phase power, phase current, sub-metered group current); the device's own draws are never waited for. Reason: live, the go-e's currents report only on change, so a draw fresh at the command went silent once steady and held nearly every window to the 90 s hard timeout (verdict timed_out). - 2026-10-29 — Hourly balance baseline (0.11.4, supersedes "never the first report after :00"): with no usable report at or before :00 the baseline is the first report of the running hour instead of leaving the balance unknown until the next :00. Reason: after any restart or a start inside the hour the dashboard showed no balance for up to an hour. Trade-off: that hour's balance omits the energy before the first report; no UI flag.
- 2026-10-29 — A series time without a UTC offset (Forecast.Solar `watts` keys, `2026-10-29 07:00:00`) is read as wall-clock time in the add-on's zone (`TimeProvider.LocalTimeZone`, the zone of the slot grid), not UTC and not refused; `SubscribeEntitiesParser`/`SeriesAttributeParser` take the zone, and without one such a time is still refused. Reason: the maintainer's HA sums the three planes into a template sensor `sensor.pv_forecast_watts` whose `watts` dict has local keys; the add-on's zone must be HA's. A local time that does not exist (spring gap) moves one hour on, one that happens twice is the first (as `GoalDeadlines`); two keys landing on one instant still refuse the series. Values stay instantaneous W, integrated as the trapezoid, so the 0 W sunrise and sunset points leave no gap.
